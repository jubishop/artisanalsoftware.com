# PodHaven screenshot inventory

Prepared 2026-09-04 for the website refresh. **29 captures: 19 new and 10 refreshed.** Each ID is already wired to its feature and guide placements. Existing images are retained until replacements arrive; missing images have clearly labeled spaces in the draft.

The linked site routes describe the draft layout and will be public after publication.

## Capture setup

- Use the current app build and one consistent iPhone size. Send original full-resolution PNG files, without device frames or markup; the site adds the frame.
- Use dark appearance for the main set. The light-mode capture is the deliberate exception. Keep text at a readable, consistent size, with slightly larger Dynamic Type for the light-mode example.
- Choose readable episode titles, varied artwork, and useful real data. Clear unrelated notifications and avoid private feeds or identifying personal content.
- Name each file with the ID below plus `.png`. The exact capture matters more than matching the filename; files can be renamed when supplied.
- Prioritize Up Next, recommendation details/settings, Smart Lists and its rule editor, podcast settings, and swipe settings. The Smart Lists overview appears in the homepage hero. The player transcript appears in a smaller callout near the bottom of the homepage; the remaining transcript captures support its feature page and guide.

## Installing the supplied images

Place captures in `public/images/podhaven/screenshots/<id>.png`, then restart the Node server. The server chooses a new image when present and otherwise keeps the existing capture or labeled placeholder. A shared screenshot definition supplies the alt text and caption, so one replacement updates every placement. Review the image and adjust its alt text if the capture differs.

There are 29 primary slots: 19 new captures and 10 refreshed captures. If podcast settings need two captures, the optional `podcast-settings-lower.png` is an additional image to wire in after it is supplied. Keep any extra captures for useful guide details.

Run `npm test`, then review the homepage and affected guides at desktop and phone widths. Existing CSS and screenshot URLs use content hashes for cache invalidation. Confirm there are no remaining missing-capture spaces before a final publication, unless intentionally publishing the draft.
